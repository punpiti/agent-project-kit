# 14 — Web Development

Use for websites, web applications, APIs serving web clients, frontend work,
backend integration, accessibility, performance, and deployment-related code.

## Route

1. Identify the requested user-visible outcome and affected page/flow.
2. Inspect only the relevant framework, route, component, API, and tests.
3. Separate visual/product judgment (L2) from implementation correctness (L1).
4. Define acceptance criteria for behavior, responsive layout, accessibility,
   error/loading states, and compatibility that matter to this request.
5. Reuse existing design system and project conventions.
6. Run the smallest relevant test first; expand only when risk warrants it.
7. Do not start dev servers, install dependencies, rebuild assets, or run broad
   browser suites if a valid prior setup/result exists and the task does not
   require revalidation.

Use `03_CODEX_CODING_AGENT.md` as a secondary workflow for substantial code
changes. Use product/design context only when the requested outcome needs it.
