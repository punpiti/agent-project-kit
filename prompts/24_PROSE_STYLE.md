# Prose Style Quality Gate — เขียนร้อยแก้วให้ตรง กระชับ และไม่มีลีลาแบบ AI

Quality gate ใช้ทุกครั้งที่ร่างหรือแก้ **ร้อยแก้วที่ผู้อ่านจะอ่านจริง** ไม่ว่าภาษาไทยหรืออังกฤษ
เช่น บทความวิจัย รายงาน บทหนังสือ proposal จดหมาย หรือคำชี้แจงต่อผู้ทรงคุณวุฒิ
ไม่ใช้กับ code comment, commit message หรือไฟล์ state ภายใน `.ai/`

หลักใหญ่มีข้อเดียว: **ทุกประโยคต้องพาข้อมูลใหม่หรือเหตุผลใหม่มาให้ผู้อ่าน**
ลีลาที่คนจับได้ว่าเป็น AI ส่วนใหญ่คือประโยคที่มีรูปแต่ไม่มีเนื้อ

## 1. สิ่งที่ต้องทำ

1. **ประโยคแรกของย่อหน้าบอกประเด็นของย่อหน้า** ผู้อ่านที่อ่านแค่ประโยคแรกของทุกย่อหน้าต้องเข้าใจเรื่องทั้งหมด
   ห้ามเปิดด้วยประโยคบอกโครงสร้าง ("Three readings follow.") หรือประโยคชี้ตาราง ("Table 3 gives…") ในส่วนผลลัพธ์ ให้เปิดด้วยผล
2. **ส่วนที่เหลือของย่อหน้าต้องรองรับประโยคแรก** ด้วยตัวเลข อ้างอิง หรือเหตุผล ถ้าประโยคไหนไม่รองรับ ให้ย้ายหรือตัด
3. **หนึ่งย่อหน้าหนึ่งประเด็น** ย่อหน้าที่มีสองเรื่องให้แยก ย่อหน้าประโยคเดียวที่เป็นแค่ตัวเชื่อมให้รวมกับย่อหน้าถัดไป
4. **เขียนตรง** บอกสิ่งที่เป็น แทนการบอกสิ่งที่ไม่เป็นแล้วค่อยหักกลับ
5. **ข้อจำกัดบอกเต็มครั้งเดียว** ในที่ที่เหมาะที่สุด ที่อื่นอ้างกลับด้วยประโยคสั้น
6. **เรียกสิ่งเดียวกันด้วยชื่อเดียวตลอด** และนิยามตัวย่อ สัญลักษณ์ ชื่อย่อก่อนใช้ครั้งแรก
7. **ความแรงของคำต้องเท่ากับความแรงของหลักฐาน** ผลเชิงสัมพันธ์ใช้ "consistent with" ไม่ใช้ภาษาเชิงเหตุ
8. **สลับประโยคสั้นยาว** ประโยคยาวที่ต่อด้วย semicolon หรือ colon หลายท่อนให้แตกเป็นประโยคสั้น

## 2. รูปแบบที่ต้องหลีกเลี่ยง

| รูปแบบ | ตัวอย่างที่ชวนสะดุด | เขียนแทน |
|---|---|---|
| หักมุมแบบสูตร "not X, but Y" / "ไม่ใช่… แต่เป็น…" | "This is not a flaw, but a feature." | บอก Y ตรง ๆ: "This is a feature." |
| รูปใกล้เคียง: "X, not Y", "rather than", "instead of" ใช้ถี่ | "a statement about risk, not evidence of leakage" | ใช้เฉพาะเมื่อการเปรียบเทียบมีสาระ ไม่เช่นนั้นตัดครึ่งหลัง |
| "มากกว่าแค่…" / "more than just…" | "งานนี้เป็นมากกว่าแค่การจำแนกภาพ แต่เป็น…" | บอกว่างานทำอะไร |
| ถามแล้วตอบเอง | "What does this mean? It means…" | "This means…" |
| สามคำสวย ๆ ที่ไม่ได้อธิบายต่อ | "accurate, transparent and sustainable" | ใช้รายการเฉพาะเมื่อทุกข้อถูกอธิบายหรือใช้จริง |
| เปิดด้วยฉากใหญ่เกินเรื่อง | "ในยุคที่ AI กำลังเปลี่ยนแปลงโลก…" | เปิดด้วยปัญหาเฉพาะของงาน |
| หักมุมที่ไม่มีความขัดแย้งจริง | "Although X, Y" ที่ X กับ Y ไม่ขัดกัน; "nonetheless" ลอย ๆ | ใช้คำเชื่อมเชิงขัดแย้งเฉพาะเมื่อสองฝั่งขัดกันจริง |
| สรุปความสำคัญลอย ๆ | "has important implications for the field" | บอกว่าใครต้องทำอะไรต่างไปจากเดิม |
| ปิดท้ายเป็นคำคม | "The leaf was not required for it." / "อนาคตรอให้เราร่วมกันสร้าง" | ปิดด้วยข้อเท็จจริงหรือข้อสรุปที่วัดได้ |
| ประโยคบอกโครงสร้างแทนสาระ | "This is the gap." / "Three things follow." | ตัดทิ้ง แล้วขึ้นต้นด้วยประเด็นจริง |
| อธิบายเหตุผลของตัวเองซ้ำ ๆ | "We report this because…", "We record this because…" | ใช้เฉพาะเมื่อเหตุผลนั้นเป็นข้อมูลที่ผู้อ่านต้องรู้ |
| พูดกับผู้อ่านหรือสั่งผู้อ่าน | "a reader should be able to check…", "must not be read as…" | บอกข้อเท็จจริง แล้วให้ผู้อ่านสรุปเอง |
| คำเน้นเกินจำเป็น | precisely, exactly, genuinely, crucially, importantly, "อย่างยิ่ง", "นั่นเอง" | ตัด ถ้าประโยคยังจริงเท่าเดิม |
| ตัวหนาเน้นกลางประโยค | "**This is the key finding.**" | ตัวหนาใช้กับหัวข้อ หัวตาราง ป้ายเท่านั้น; เน้นศัพท์ที่นิยามด้วยตัวเอียง |
| em dash, semicolon, colon ถี่ | ประโยคที่มี "—…—" และ ";" หลายตัว | แตกประโยค |
| hedge ซ้อน | "may potentially suggest a possible…" | hedge ครั้งเดียวให้ตรงกับหลักฐาน |
| วลีเติม | "It is worth noting that", "In this regard", "นอกจากนี้ยัง… อีกด้วย", "กล่าวคือ" ต่อกันเป็นทอด | ตัดวลี เหลือเนื้อความ |

**สิ่งที่ไม่ต้องหลีกเลี่ยง:** การเปรียบเทียบที่มีข้อมูลสองฝั่งจริง เช่น "0.944 within camera, 0.752 across";
ข้อจำกัดที่จำเป็นต่อการตีความ; ศัพท์เทคนิคที่แม่นยำ อย่าแก้จนประโยคขาดเป็นท่อนหรือเสียความแม่นยำ

## 3. เกณฑ์ตรวจเชิงปริมาณ

ตัวเลขข้างล่างเป็น **สัญญาณให้ตรวจ ไม่ใช่ข้อห้ามตายตัว** ค่านี้ได้จากการเกลาต้นฉบับวิจัยจริงหนึ่งเรื่อง
(Ecological Informatics, 2026) ถ้าเกินให้อ่านทุกจุดในบริบทแล้วตัดสินทีละจุด

| ตัวชี้วัด | ต้องเป็นศูนย์ | ตรวจเมื่อเกิน (ต่อ 1,000 คำ) |
|---|---|---|
| "not X, but Y" / "ไม่ใช่… แต่เป็น…" | ✔ | – |
| "more than just" / "มากกว่าแค่" | ✔ | – |
| เครื่องหมายคำถามในเนื้อความ | ✔ (ยกเว้นยกคำถามวิจัย) | – |
| ตัวหนากลางประโยค | ✔ | – |
| "rather than" / "instead of" | | 1.0 |
| ", not …" | | 0.7 |
| semicolon | | 3.0 |
| em dash | | 1.5 |
| ประโยคที่มี colon อธิบายต่อ | | 2.5 |
| คำเน้น (precisely, exactly, genuinely, crucially, importantly) | | 0.5 |

สคริปต์ช่วยนับ: `python3 .ai/agent-project-kit/scripts/check_prose_style.py <file.tex|.md|.txt>`
รองรับ LaTeX (ตัดคอมเมนต์และคำสั่งพื้นฐานก่อนนับ) และ Markdown สคริปต์รายงานจำนวน อัตรา และบรรทัดของจุดที่ต้องเป็นศูนย์
การตัดสินสุดท้ายต้องอ่านบริบทเสมอ

## 4. ขั้นตอนเกลา

1. **ล็อกเนื้อหาก่อน** เกลาภาษาหลังตัวเลข ข้อสรุป และโครงสร้างนิ่งแล้ว เพื่อไม่ต้องเกลาซ้ำ
2. **รันสคริปต์** แล้วแก้กลุ่ม "ต้องเป็นศูนย์" ให้ครบก่อน
3. **อ่านประโยคแรกของทุกย่อหน้าเรียงกัน** ถ้าอ่านแล้วไม่ได้เรื่อง ให้แก้ประโยคแรกและปรับประโยคอื่นในย่อหน้าให้รับกัน
4. **ไล่ประโยคสุดท้ายของทุก section** ตัดคำคมและบทสรุปลอย
5. **ลดกลุ่มที่เกินเกณฑ์** ทีละรูปแบบ แก้เฉพาะจุดที่เป็นลีลา ไม่แก้จุดที่เปรียบเทียบข้อมูลจริง
6. **ห้ามเปลี่ยนตัวเลข ข้อเท็จจริง หรือความแรงของข้ออ้างระหว่างเกลา** ถ้าเจอปัญหาเนื้อหา ให้แยกรายงาน
7. **รัน QA เดิมของ project ซ้ำ** (build, citation, จำนวนคำ, overflow) เพราะการตัดคำเปลี่ยนการตัดบรรทัดและจำนวนคำได้
8. **รายงานผู้ใช้** เป็นตาราง รูปแบบ → จำนวนก่อน/หลัง → ตัวอย่างที่แก้ และจุดที่ตั้งใจคงไว้พร้อมเหตุผล

## 5. เฉพาะภาษาไทย

- หลีกเลี่ยง "ไม่ใช่… แต่เป็น…", "มากกว่าแค่…", "ในยุคที่…", "ถือเป็นก้าวสำคัญ", "…นั่นเอง" ท้ายประโยค
- "อย่างไรก็ตาม" ใช้เมื่อมีความขัดแย้งจริง ไม่ใช้เป็นคำขึ้นย่อหน้าทั่วไป
- "นอกจากนี้… ยัง… อีกด้วย" และ "กล่าวคือ" ที่ต่อกันหลายทอด ให้แตกเป็นประโยคตรง
- คำอังกฤษเฉพาะทางที่ไม่มีคำไทยแพร่หลาย เขียนทับศัพท์หรือวงเล็บครั้งแรกแล้วใช้คำเดิมตลอด
