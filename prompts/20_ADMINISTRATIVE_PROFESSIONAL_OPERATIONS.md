# 20 — Administrative & Professional Operations

Use for compliance tracking, deadlines, formal submissions, correspondence,
nomination/application dossiers, meeting follow-up, document control, and
professional case management.

## Route

1. Identify the required outcome, authority/recipient, deadline, source of the
   requirement, and current status.
2. Separate verified facts, inferred status, missing evidence, and actions.
3. Build the smallest actionable checklist ordered by deadline and dependency.
4. Reuse verified document inventories and status records; do not rescan folders
   or re-extract documents unless inputs changed.
5. Check completeness, required format, approvals/signatures, naming, delivery
   channel, confidentiality, and proof of submission.
6. Draft communications with explicit owner, requested action, and response date.
7. Never mark submitted, accepted, approved, or complete without evidence.

## Project Radar

When one person needs to remember unfinished work across several projects, use
one small `PORTFOLIO_COORDINATION.md` in a designated personal work hub. Do not
create a copy in every project; each project's `.ai/PROJECT_STATE.md` remains
the local source of truth.

### Work-Hub Discovery

When the user asks about several projects together, overall priority,
unfinished work, or forgotten/stale projects:

1. Check whether a Portfolio Operations hub path has already been named. Read
   that hub only for this cross-project request; never load it at ordinary
   project startup.
2. If no hub exists, say so and offer to create one outside a project repository
   (for example, a user-selected `OneDrive/work-hub` folder). Create it only
   after the user authorizes that path.
3. Create only `README.md` and `PORTFOLIO_COORDINATION.md` from the supplied
   work-hub templates. The one-row-per-project Project Pulse is the entire
   normal record.
4. During weekly review, flag every row not reviewed for 14+ days and classify
   it as active, blocked, intentionally parked, or forgotten. Old does not mean
   done.
5. Never duplicate task lists, transcripts, logs, or project details in the
   radar; those stay in the project itself.

Load Educational Policy Development only when rules or institutional decisions
are being designed, rather than merely followed or administered.
