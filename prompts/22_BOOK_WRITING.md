# วิธีสร้างร้อยแก้วของต้นฉบับ

## ลำดับอำนาจและสัญญา output ของหนังสือ — ต้อง resolve ก่อนใช้วิธีนี้

วิธีนี้กำหนด **ลอจิกการสร้างและตรวจร้อยแก้ว** ไม่ได้กำหนดรูปเล่มหรือ
toolchain กลางให้หนังสือทุกเล่ม ค่า source format, ชื่อไฟล์ทำงาน, โครง chapter,
output format, ขนาดหน้า/จอ, font, citation style, anchor syntax, equation/table/
figure syntax, build command, draft/production separation และเกณฑ์ QA ต้องอ่านจาก
ข้อกำหนดของโครงการหนังสือเป้าหมายตาม `{{PROFILE:output-production-contract}}`
ส่วนระดับผู้อ่าน เป้าหมายการเรียนรู้ ภาษาหลัก และบริบทการนำไปใช้ต้อง resolve จาก
`{{PROFILE:reader-domain-contract}}` เช่นกัน ห้ามถือว่านักศึกษาปริญญาตรีหรือ
ผู้อ่านสายวิศวกรรมเป็นค่าเริ่มต้นของหนังสือทุกเล่ม

ลำดับอำนาจเมื่อคำสั่งชนกันคือ:

1. ข้อกำหนดที่ผู้ใช้ให้สำหรับหนังสือเป้าหมายและไฟล์ project-local ที่ผู้ใช้รับรอง
2. `BOOK_WRITING_PROFILE.md` ที่ resolve จากโครงการเป้าหมายนั้น
3. ลอจิก evidence-first, pre-prose gate และ prose QA ในวิธีนี้
4. ตัวอย่างชื่อไฟล์ Markdown/PDF/Pandoc/LaTeX, marker, anchor และ command ในเอกสารนี้
5. default ของ document-production หรือ template กลางอื่น

ข้อ 4–5 เป็นเพียง implementation example เมื่อ profile เลือกใช้เท่านั้น ไม่มีสิทธิ์
บังคับ A4, 16:9, B5, PDF, DOCX, EPUB, HTML, Markdown, Pandoc, LaTeX,
`chapter.md`, `prose.md` หรือ directory layout ใด หาก project กำหนดต่างออกไป
ให้ถ่ายทอด **หน้าที่** เดิมไปยังโครง native ของ project เช่น แยก working evidence
กับ reader-facing manuscript, ใช้ stable cross-reference และมี draft/final QA
โดยไม่สร้าง frame ซ้ำขึ้นมาแข่งกับ source of truth เดิม หากหา output contract ไม่พบ
หรือพบข้อกำหนดขัดกัน ให้ถามผู้ใช้ก่อน build หรือเปลี่ยนโครงไฟล์

เพื่อรักษาความคมของวิธีเดิมโดยไม่บังคับ frame เดิม คำว่า `chapter.md` ต่อจากนี้
หมายถึง **working evidence/outline source** ของ project, `prose.md` หมายถึง
**reader-facing manuscript source**, heading `#`–`####` หมายถึงระดับโครงเรื่องที่
เทียบเท่ากัน และ “Draft PDF” หมายถึง **draft output ที่ project กำหนด** หาก project
ใช้ชื่อไฟล์ format หรือ hierarchy ต่างออกไป ให้ map บทบาทเหล่านี้ไว้ใน profile
แล้วใช้ชื่อ native นั้นตลอด ห้ามสร้างไฟล์ Markdown/PDF คู่ขนานเพียงเพื่อทำตามคำ
ตัวอย่างในวิธีนี้

## หลักการ

ร้อยแก้วของแต่ละหัวข้อ `###` เขียนจาก bullet ใต้ marker `#### ประเด็นที่จะอธิบายตามลำดับ` ใน `chapter.md` โดยรักษาลำดับเหตุผลและความสัมพันธ์ที่พบจากแหล่งอ้างอิง ไม่ใช่นำ bullet มาต่อเป็นประโยคเฉย ๆ Marker ดังกล่าวเป็นส่วนจัดการหลักฐาน ไม่ได้บังคับให้สร้างหัวข้อ `####` ใน `prose.md`

- **{{PROFILE:primary-teaching-source-label}} กำหนดสาระขั้นต่ำที่ห้ามตัดออก** แหล่งอ้างอิงแนะนำใช้ตรวจความถูกต้อง หาโครงลอจิก และขยายคำอธิบาย
- ทุกประเด็นและความสัมพันธ์ต้องสืบกลับไปยังข้อความ/ภาพ/ตาราง/สมการที่ **เปิดอ่านจริง** ห้ามสร้างจากความรู้เดิม ห้ามเดา ห้ามใส่ citation ให้ข้อความที่ยังไม่ตรวจพบ

กฎตัดสินย่อ (ใช้ตอบคำถาม "ควรทำอะไรต่อ" ได้ทันที):

`ไม่พบใน ref ที่อ่านจริง` → `ไม่สร้าง bullet` → `ไม่เขียนร้อยแก้ว` → `ไม่ใส่ citation`
`{{PROFILE:primary-teaching-source-label}} มีสาระ` → `ต้องคงไว้และหา ref รองรับเพิ่ม ไม่ใช่ตัดทิ้ง`
`ref มีรายละเอียดพอ` → `ขยายถึง nested ระดับ 3 แล้วถ่ายทอดลงร้อยแก้ว`
`ref ไม่มีรายละเอียดพอ` → `ลดเหลือ nested 2 ระดับ หรือใส่ marker โดยไม่มโน`

## สัญญาการเขียนฉบับย่อสำหรับ run-through

ใช้รายการนี้เป็นสัญญาหลักระหว่างเขียนจริง หากรายละเอียดส่วนอื่นอ่านได้หลายทาง ให้ยึดรายการนี้ก่อน:

1. **ฐานเนื้อหา:** เขียนจาก main+nested bullet ของ `chapter.md` รุ่นที่ผ่าน pre-prose gate เท่านั้น; ทุกข้อเท็จจริงต้องย้อนกลับไปยังหลักฐานที่เปิดอ่านจริง
2. **หน่วยร้อยแก้ว:** หนึ่ง main bullet เท่ากับหนึ่งหน่วยเหตุผลที่ติดตามย้อนกลับได้ โดยปกติใช้หนึ่งย่อหน้า แต่แบ่งเป็นหลายย่อหน้าได้เมื่อช่วยจังหวะการอ่านและทุกย่อหน้ายังอยู่ในขอบเขต bullet เดิม เนื้อหาต้องสังเคราะห์ nested bullet ไม่ใช่ถอด bullet เป็นประโยค และเป้าประมาณ 5 บรรทัดใช้เป็นแนวทางต่อย่อหน้าใน Draft PDF {{PROFILE:draft-page-size}} เมื่อหลักฐานพอ
3. **ลำดับหัวข้อ:** เขียนเนื้อหาหลักของ `###` ก่อน; สร้าง `####` เฉพาะเมื่อมีอย่างน้อยสองกลุ่มเนื้อหาย่อยที่แยกหน้าที่กันจริง แล้วจึงย้อนเขียนเกริ่นนำ `###` เฉพาะกรณีที่มี `####`; เขียนบทนำ `##` หลัง `###` ภายในครบ และเขียนบทนำ `#` หลังทั้งบทครบ
4. **องค์ประกอบประกอบคำอธิบาย:** รูป ตาราง และสมการต้องมีข้อความชี้แยก, stable anchor และ caption/เลข/คำอธิบายตามชนิด ข้อความชี้ไม่นับเป็นหน่วยร้อยแก้วของ main bullet; worked example เป็น standalone ได้
5. **สถานะงาน:** สิ่งที่ยังขาดใช้ `needs-*`; ภาพสไลด์ชั่วคราวต้องมี `ref-note`; citation, ภาพสไลด์ และ `ref-note` คงอยู่ใน Markdown เสมอ
6. **การตรวจหัวข้อ:** ก่อนขยับไป `###` ถัดไป ต้องตรวจว่า main bullet ทุกข้อมีหน่วยร้อยแก้วที่ติดตามได้โดยไม่บังคับจำนวนย่อหน้าเท่ากัน รวมทั้งตรวจความครบของสาระ {{PROFILE:primary-teaching-source-label}}, citation, ศัพท์, marker, anchor และข้อความชี้องค์ประกอบของหัวข้อปัจจุบัน
7. **การปิดบท:** เมื่อครบทุก `###` จึงตรวจทั้งบท, เพิ่ม pointer ใน `chapter.md` โดยไม่ลบหลักฐาน, build Draft PDF, ตรวจภาพจริง/ข้อความสกัด และ commit ตามลำดับ draft → QA → approved
8. **Production แยกจาก source:** Draft build ใช้ตรวจ author-only material; production profile ในอนาคตต้องกรอง citation ภายใน ภาพสไลด์ และ `ref-note` ออกจากผลลัพธ์ และต้อง fail หากยังมี `needs-*` โดยไม่ลบสิ่งเหล่านี้จาก Markdown

## ลำดับงานทั้งหมด (ทำครั้งเดียว ไม่ใช่วนซ้ำ 3 รอบ)

1. อ่าน `โซนข้อความจาก {{PROFILE:primary-teaching-source-label}}` + ตรวจภาพสไลด์ → ได้สาระบังคับขั้นต่ำของหัวข้อ
2. เปิดอ่านส่วนจริงของ `แหล่งอ้างอิงแนะนำ` ตาม `{{PROFILE:large-reference-ingestion-procedure}}` (ห้ามใช้ชื่อบท/สารบัญ/thumbnail แทนเนื้อหา) → หานิยาม เหตุผล กลไก ตัวเลข ขอบเขต ข้อยกเว้น ลำดับการอธิบาย
3. สกัดเป็น **หน่วยหลักฐาน** และบันทึก **reading cache** (ดูหัวข้อถัดไป)
4. จับคู่สาระ {{PROFILE:primary-teaching-source-label}} กับหน่วยหลักฐาน: {{PROFILE:primary-teaching-source-label}}+ตำรารองรับ → เป็นแกนของประเด็น; ตำราแก้ไข/จำกัดสาระ {{PROFILE:primary-teaching-source-label}} → ใช้คำอธิบายที่แม่นกว่าจากตำรา; {{PROFILE:primary-teaching-source-label}} อย่างเดียว → อ้าง `[{{PROFILE:primary-teaching-source-citation-code}} locator]` โดยไม่ขยายเกินสิ่งที่ source แสดง
5. จัดกลุ่มหน่วยหลักฐานเรื่องเดียวกัน เรียงตามลอจิกที่ปรากฏในแหล่งอ้างอิง (ยังไม่เพิ่มข้อสรุปใหม่)
6. เขียน `#### ประเด็นที่จะอธิบายตามลำดับ` เป็น main bullet + nested bullet ตามกฎในหัวข้อ "การสร้างประเด็น" ด้านล่าง
7. ตรวจย้อนกลับทีละ bullet ว่าชี้หลักฐานต้นทางได้ทันที — ชี้ไม่ได้ให้ลบ, หลักฐานไม่พอให้เว้นว่างไว้ค้นเพิ่ม, ถ้าเป็นการตัดสินใจเชิงหลักสูตร/โครงหนังสือให้ระบุว่าเป็นดุลยพินิจผู้เขียน ไม่แอบอ้างว่ามาจากตำรา
8. เมื่อทุกหัวข้อ `###` ของทั้งบทผ่านขั้นตอน 1–7 แล้ว รัน **การตรวจสอบก่อนเขียนร้อยแก้ว** (สคริปต์ตรวจทั้งบทครั้งเดียว) ก่อนเริ่มเขียนร้อยแก้วจริง
9. เขียนร้อยแก้วของแต่ละ `###` ลงใน **`prose.md`** (ไม่ใช่ `chapter.md`) ตามลำดับ bullet หากเนื้อหาแบ่งเป็นอย่างน้อยสองกลุ่มซึ่งผู้อ่านต้องใช้ชื่อกลุ่มช่วยนำทาง จึงสร้าง `####` ให้แต่ละกลุ่มและเขียนเกริ่นนำ `###` ย้อนกลับไปไว้ก่อน `####` แรก; หากมีเพียงกลุ่มเดียว ให้เขียนตรงใต้ `###` โดยไม่สร้าง `####` จาก marker ใน `chapter.md` จากนั้นจึงเพิ่มบรรทัดชี้กลับไปยัง `prose.md` โดยไม่ลบ bullet หลักฐาน
10. เมื่อทุก `###` ในหัวข้อ `##` หนึ่งเสร็จแล้ว เขียนบทนำระดับ `##` นั้นลงใน `prose.md` ทำแบบนี้ให้ครบทุกหัวข้อ `##` ของบท แล้วจึงเขียนบทนำระดับ `#` เป็นลำดับสุดท้าย (ดูหัวข้อ "บทนำระดับ `#`, `##` และ `###`") — บทนำทุกระดับเขียนหลังเนื้อหาลูกเสร็จเสมอ เพราะต้องสะท้อนเนื้อหาจริงที่เขียนไว้แล้ว ไม่ใช่คาดเดาล่วงหน้า

## เกณฑ์พร้อมเดินหน้าเขียนให้จบทั้งบท

เมื่อครบเงื่อนไขต่อไปนี้แล้ว ให้ถือว่าวิธีเขียนของบทนั้นนิ่งพอและเดินหน้าเรียงหัวข้อจนจบบทได้ ไม่หยุดออกแบบรูปแบบใหม่ซ้ำทุก `###`:

1. `chapter.md` ผ่านการตรวจสอบก่อนเขียนร้อยแก้วทั้งบทแล้ว ทั้งโครงสร้าง ความลึกของ nested bullet, evidence ledger, citation และการตรวจ fake nesting ด้วยสายตา
2. เขียนหัวข้อตัวอย่างอย่างน้อยหนึ่ง `###` จาก outline รุ่นปัจจุบันและตรวจแล้วว่าใช้สัญญาครบ ได้แก่ main bullet ทุกข้อมีหน่วยร้อยแก้วที่ติดตามได้, ไม่มี `####` ลูกเดียว, กรณีมี `####` หลายกลุ่มต้องมีเกริ่นนำก่อนกลุ่มแรก, ศัพท์และ citation ถูกต้อง, ภาพสไลด์อยู่ถูกตำแหน่ง และ marker ครบ
3. รูป ตาราง และสมการในหัวข้อตัวอย่างมีข้อความชี้องค์ประกอบ, stable anchor, เลขอ้าง และ caption/คำอธิบายตามชนิด โดยย่อหน้าชี้องค์ประกอบไม่นับรวมกับเป้าความยาวประมาณ 5 บรรทัดของ main bullet; ตัวอย่างคำนวณอนุญาตให้เป็น standalone ตามกรอบสี่ส่วน
4. Draft PDF build ผ่านและตรวจว่า heading ไม่ซ้อนติดกัน, `\ref`/`\eqref` resolve ไม่มี `??`, เลขรูป/ตาราง/สมการต่อเนื่อง และ marker แสดงสถานะถูกชนิด

หลังผ่านเกณฑ์นี้ ให้ทำตามลำดับต่อไปนี้จนจบโดยไม่ข้ามขั้น:

1. เขียน `###` ถัดไปตามลำดับใน `chapter.md` และตรวจรับระดับหัวข้อย่อยทันที โดยใช้หัวข้อตัวอย่างที่ผ่านแล้วเป็นแม่แบบ
2. เมื่อกลุ่ม `####` หลายกลุ่มภายใน `###` เสร็จ จึงเขียนเกริ่นนำ `###`; ถ้า `###` ไม่มี `####` ให้ร้อยย่อหน้าแรกเข้ากับเนื้อหาโดยตรง ไม่สร้างเกริ่นแยกเพียงเพื่อรักษารูปแบบ; เมื่อทุก `###` ภายใน `##` เสร็จ จึงเขียนบทนำ `##`; และเขียนบทนำ `#` หลังทุก `##` เสร็จแล้วเท่านั้น
3. เมื่อร้อยแก้วครบทั้งบท ให้ตรวจความครอบคลุมและการติดตามย้อนกลับจาก main bullet สู่หน่วยร้อยแก้วโดยไม่บังคับจำนวนย่อหน้าเท่ากัน พร้อมตรวจข้อความชี้องค์ประกอบ/anchor/caption, รูปสไลด์+`ref-note`, marker, citation, ศัพท์, สมการ และตัวอย่างคำนวณอีกครั้งในระดับทั้งบท
4. เพิ่ม pointer จาก `chapter.md` ไปยัง anchor ของ `prose.md`, build และตรวจ Draft PDF ทั้งบท แล้ว commit เป็น prose draft แยกจาก commit ของ prose QA และ approved manuscript ตาม `VERSIONING_POLICY.md`

## หน่วยหลักฐานและ reading cache

- หน่วยหลักฐานหนึ่งหน่วย = ข้อความ/ภาพ/ตาราง/สมการหนึ่งประเด็น พร้อมแหล่ง ฉบับ บท หัวข้อ และเลขหน้า/สไลด์ที่ตรวจสอบได้ ถอดความรักษาความหมาย เงื่อนไข และขอบเขตเดิม

- ทุกหัวข้อ `### x.x.x` ต้องมี `references/EVIDENCE_x.x.x.md` (ตารางหน่วยหลักฐาน) คู่กันเสมอ

## การสร้าง `#### ประเด็นที่จะอธิบายตามลำดับ`

**Main bullet**: ประโยคบอกเล่าความรู้หนึ่งเรื่องต่อหนึ่ง bullet ไม่ใช้ถ้อยคำ workflow ("เริ่มจาก" "ให้อธิบาย" "ให้ผู้เรียน" "สาธิต" "ทบทวน" "ปิดด้วย") อ่านเข้าใจได้ด้วยตัวเองโดยไม่ต้องอาศัยหัวข้อก่อนหน้า ไม่รวมหลายข้อสรุปด้วยคำว่า "และ" หากแยกเป็นคนละ bullet ได้ เรียงตามลอจิกของแหล่งอ้างอิง (เช่น ขอบเขต → การจำแนก → บทบาท → การประยุกต์ → ข้อจำกัด) ไม่เรียงตามที่ผู้เขียนนึกขึ้นเอง — จำนวน bullet ไม่กำหนดตายตัว มีได้มากเท่าที่จำเป็นต่อความครบถ้วนและความต่อเนื่อง

**Nested bullet — โครงสร้างมาตรฐาน 3 ระดับใต้ main bullet** (main ไม่นับเป็นระดับ):

| ระดับ | เยื้อง | หน้าที่ |
|---|---|---|
| 1 | 2 ช่องว่าง | ขยายองค์ประกอบหลักของข้อความ |
| 2 | 4 ช่องว่าง | อธิบายเหตุผล ความสัมพันธ์ หรือกลไก |
| 3 | 6 ช่องว่าง | รายละเอียด ตัวเลข ตัวอย่าง ข้อยกเว้น หรือขอบเขตจากหลักฐาน |

ลดเหลือ 2 ระดับได้เฉพาะเมื่อ {{PROFILE:primary-teaching-source-label}} และ ref ที่อ่านจริงไม่มีรายละเอียดพอสำหรับระดับ 3 — การใช้ระดับ 3 ต้องเพิ่มความรู้หรือความสัมพันธ์จริงจากหลักฐาน ไม่ใช้เพียงเพื่อให้ครบจำนวนระดับ

**กับดักสำคัญที่สุด — nested bullet ปลอม (fake hierarchy)**: การเยื้องต้องสื่อความสัมพันธ์แบบ **สืบทอด/เฉพาะเจาะจงขึ้น** เท่านั้น (นิยาม → เหตุผล/ที่มา → ตัวเลขหรือตัวอย่างที่ตามมาโดยตรง) ห้ามใช้การเยื้องแทน:

- **ลำดับ/ขั้นตอนที่เท่ากัน** (ขั้น 1, 2, 3 ของกระบวนการเดียวกัน) → ให้เป็น main bullet แยกกันคนละระดับเดียวกัน
- **กรณีคู่ขนาน/พิเศษของกฎเดียวกัน** (เช่น สูตรทรงกระบอก/ทรงกลม/ฟองสบู่ที่เป็นกรณีพิเศษของสูตรทั่วไปเดียวกัน) → เป็นพี่น้องระดับเดียวกัน ไม่ใช่กรณีหนึ่งเป็นแม่ของอีกกรณี
- **การเปรียบเทียบ/ขัดแย้งกัน** ("น้ำเปลี่ยนน้อย *ตรงกันข้าม* อากาศเปลี่ยนมาก") → เป็นพี่น้องระดับเดียวกัน

สัญญาณเตือน: ประโยคขึ้นต้นด้วย "ตรงกันข้าม" "ในทำนองเดียวกัน" "เช่นเดียวกับที่..." "นอกจาก...ยัง...ด้วย" แล้วถูกเยื้องเป็นลูกของ bullet ก่อนหน้า — ให้ถามว่าความสัมพันธ์จริงคือ "สืบทอดมาจากกัน" หรือแค่ "พูดเรื่องเดียวกันต่อ" ถ้าเป็นแบบหลัง ให้ลดกลับเป็นพี่น้องแม้ความลึกจะไม่ถึง 3 ระดับ (การลดเหลือ 2 ระดับครอบคลุมกรณีนี้ด้วย ไม่ใช่แค่กรณีข้อมูลไม่พอ)

**Citation และตาราง/รูป/สมการ**:

- ทุก bullet ต้องมี citation พร้อม **source-native locator** ที่ตรวจพบจริงและละเอียดพอให้เปิดกลับได้ เช่น page+section สำหรับ PDF, heading/paragraph/table สำหรับ DOCX, slide+object/notes สำหรับ PPTX หรือ locator ที่ format/โครงการกำหนด ไม่ใช้เพียงชื่อบท/ไฟล์กว้าง ๆ วางไว้ใกล้ข้อความที่รองรับ — citation เองไม่ใช่หลักฐานว่าตรวจแล้ว ต้องเปิดอ่านและชี้ตำแหน่งได้จริง
- เมื่อหน่วยหลักฐานอ้างถึงตาราง/รูป/สมการ**หรือตัวอย่างที่แก้แล้ว (worked example)** ของแหล่งอ้างอิง (ไม่ใช่แค่ข้อความบรรยาย) ต้องมี bullet ระบุชัดว่ามีสิ่งนั้นอยู่ เช่น `**[มีตารางประกอบ {{PROFILE:example-primary-reference-author}} Table A.5]** ...`, `**[มีรูปประกอบ Fig. 1.9a]** ...` หรือ `**[มีตัวอย่างประกอบ {{PROFILE:example-primary-reference-author}} Example 1.6]** ...` เพื่อให้ผู้เขียนร้อยแก้วรู้ตำแหน่งที่ต้องเตรียมภาพ/ตาราง/สมการ/ตัวอย่าง

**ขอบเขต bullet**: แคบพอให้ขยายเป็นหน่วยเหตุผลหนึ่งหน่วยสำหรับผู้อ่านตาม `{{PROFILE:reader-domain-contract}}` โดยปกติเป็นหนึ่งย่อหน้า แต่แบ่งหลายย่อหน้าได้เมื่อช่วยการอ่านและไม่แตกเป็นประเด็นหลักใหม่ หากเนื้อหากลายเป็นเหตุผลอิสระคนละข้อจึงค่อยแยก main bullet หรือเพิ่ม nested (ยังคงลึกไม่เกิน 3 ชั้น) ห้ามเติมตัวอย่าง ผลต่อการปฏิบัติ/การตัดสินใจในสาขา ความสัมพันธ์เชิงเหตุผล หรือลำดับที่ไม่ปรากฏในแหล่งที่อนุญาต

## โครงสร้างบทบาท: working evidence กับ reader-facing manuscript

ตัวอย่างต้นทางใช้ไฟล์ร้อยแก้ว `prose.md` แยกจาก `chapter.md`; project อื่นต้องใช้
ชื่อและการแยกไฟล์ตาม output contract แต่ต้องแบ่งหน้าที่เชิงตรรกะให้ชัดเจน:

- **`chapter.md`** = ไฟล์ทำงาน/หลักฐาน เก็บโครงสร้าง outline (`#`/`##`/`###`), โซนรูปและข้อความจาก {{PROFILE:primary-teaching-source-label}} แบบเต็ม, `#### ประเด็นที่จะอธิบายตามลำดับ` (bullet), และ `แหล่งอ้างอิงแนะนำ` — คือ "สเปก" ที่ใช้เขียนร้อยแก้ว ไม่ใช่ตัวหนังสือที่จะให้คนอ่านจริง
- **`prose.md`** = ไฟล์ผลลัพธ์สำหรับผู้อ่าน เก็บโครงหลัก (`#` บท → `##` หัวข้อใหญ่ → `###` หัวข้อย่อย) และใช้ `####` เฉพาะกลุ่มเนื้อหาย่อยตั้งแต่สองกลุ่มขึ้นไปซึ่งมีชื่อช่วยการอ่านจริง ไม่สร้าง `####` ลูกเดียวจาก marker ของ `chapter.md`; ไม่คัดโซนข้อความ {{PROFILE:primary-teaching-source-label}}, evidence ledger หรือ bullet หลักฐานมาซ้ำ เพื่อให้อ่านต่อเนื่องได้ในไฟล์เดียว

**สื่อภาพจากแหล่งสอนหลักต้องตามมาด้วยเมื่อมี**: เมื่อย้ายร้อยแก้วมาไว้ใน reader-facing manuscript ให้คัดสื่ออ้างอิงที่เกี่ยวข้องจาก working evidence มาแทรกไว้ **ในตำแหน่งที่ตรงกับย่อหน้าที่กล่าวถึงสื่อนั้นจริง** (ดูจาก citation `[{{PROFILE:primary-teaching-source-citation-code}} locator]`) ไม่ใช่กองรวมเป็น gallery ไว้ต้นหัวข้อ — เป้าหมายคือให้ reader-facing manuscript มีบริบทข้อความและภาพประกอบครบโดยไม่ต้องเปิด working evidence ควบคู่ ทั้งนี้สถานะ author-only/production และสิทธิ์ต้องเป็นไปตาม output contract

**ขั้นตอนเมื่อเขียนร้อยแก้วของหัวข้อ `###` หนึ่งเสร็จ**:

1. เขียนย่อหน้าร้อยแก้วต่อท้าย `###` ตามลำดับ outline; เพิ่ม `####`/`#####` เฉพาะเมื่อมีหลายกลุ่มเนื้อหาที่จำเป็นต้องแยกเพื่อช่วยผู้อ่าน ไม่ใช้ระดับหัวข้อแทน main bullet โดยอัตโนมัติ
2. แทรกภาพสไลด์ที่เกี่ยวข้องในตำแหน่งที่ถูกต้องตามที่อธิบายข้างต้น
3. ใน `chapter.md` เพิ่มบรรทัดชี้กลับไว้ใกล้ `#### ประเด็นที่จะอธิบายตามลำดับ`: `> ร้อยแก้วของหัวข้อนี้อยู่ใน [prose.md](prose.md#<anchor>)` โดย `<anchor>` คือ heading slug ของ `###` เดียวกันใน `prose.md` (ตัวพิมพ์เล็ก เว้นวรรคเป็น `-`) — **ห้ามลบหรือแทนที่** bullet, โซนรูป/ข้อความ {{PROFILE:primary-teaching-source-label}}, evidence pointer และรายการอ้างอิงเดิม เพราะ `chapter.md` ต้องคงเป็นสเปกและหลักฐานตรวจย้อนกลับ

## การเขียนร้อยแก้ว

- หนึ่ง main bullet = หนึ่งหน่วยเหตุผลที่ติดตามย้อนกลับได้ เรียงตามลำดับ bullet และสังเคราะห์ nested bullet ทุกระดับเป็นคำอธิบายต่อเนื่อง หน่วยหนึ่งแบ่งหลายย่อหน้าได้เพื่อความสะดวกในการอ่าน แต่ห้ามแยกจนลำดับเหตุผลหรือขอบเขตของ bullet เดิมขาดจากกัน
- **ชื่อหัวข้อเป็นสัญญากับผู้อ่าน** ก่อนปิดร้อยแก้วใต้ `####` ให้แยกองค์ประกอบของชื่อหัวข้อเป็นคำถามที่ต้องตอบ เช่น “ความสัมพันธ์และการใช้แนวคิดสองชนิด” ต้องตอบอย่างชัดเจนว่า (1) สองชนิดคืออะไร (2) สัมพันธ์กันอย่างไร และ (3) แต่ละชนิดใช้เมื่อใด การมีนิยามหรือองค์ประกอบเพียงหนึ่งจุดไม่นับว่าอธิบาย “ความสัมพันธ์” และการเอ่ยชื่อการประยุกต์ไม่นับว่าอธิบาย “การใช้” หากผู้อ่านยังเลือกใช้ไม่ได้ ถ้าหลักฐานไม่รองรับองค์ประกอบใด ให้เปลี่ยนชื่อหัวข้อหรือเปิด evidence gap ห้ามปล่อยชื่อกว้างกว่าเนื้อหา
- โครงย่อหน้า: `ข้อความหลัก → คำอธิบาย/เหตุผล → ตัวอย่างจาก ref (เมื่อมี) → การเปรียบเทียบหรือข้อสรุป (เมื่อหลักฐานรองรับ)` องค์ประกอบที่หลักฐานไม่มีไม่ใช่ข้อบังคับและห้ามแต่งเติมให้ครบแม่แบบ
- เป้าความยาวประมาณ 5 บรรทัดต่อย่อหน้า **เมื่อ render ใน Draft PDF ขนาด {{PROFILE:draft-page-size}} ด้วย template ของโครงการ** และเมื่อหลักฐานพอ — ไม่ใช่จำนวนบรรทัดใน editor และไม่ใช่ขั้นต่ำตายตัว ถ้าหลักฐานน้อยให้สั้นกว่านั้นได้ หากหน่วยเหตุผลยาวกว่านี้ให้แบ่งย่อหน้าตามจังหวะความคิดโดยไม่เพิ่มสาระนอก bullet ห้ามยืดด้วยการกล่าวซ้ำ ตัวอย่างสมมติ หรือข้อสรุปที่ไม่มีหลักฐาน
- ใช้ภาษากระชับ ชัดเจน ระดับปริญญาตรี ทุกประโยคต้องเพิ่มความหมาย เหตุผล ตัวอย่าง หรือข้อสรุป
- **ห้ามกล่าวถึงกระบวนการเขียนหรือชื่อแหล่งในเนื้อความ** เช่น "แหล่งสอนหลักระบุว่า" "{{PROFILE:example-primary-reference-author}} อธิบายว่า" "{{PROFILE:example-secondary-reference-author}} ยกตัวอย่างว่า" — เขียนความรู้โดยตรง แล้ววาง citation (`[{{PROFILE:primary-teaching-source-citation-code}} locator]`, `[{{PROFILE:example-primary-reference-code}} locator]`, `[{{PROFILE:example-secondary-reference-code}} locator]`) ท้ายประโยคหรือท้ายย่อหน้าที่อาศัยหลักฐานนั้น
- หากควรขยายแต่ยังไม่มีหลักฐาน ห้ามแต่งเติม ให้แทรก `::: needs-evidence` (fenced div เดียวกับ placeholder marker อื่น ๆ — ดู "Placeholder marker สำหรับสิ่งที่ยังไม่ได้เขียน") ไว้ท้ายตำแหน่งนั้น พร้อมระบุให้เจาะจงว่าขาด claim/กลไก/กรณีใดและควรหาจากแหล่งชนิดใด เช่น "หาแหล่งที่มีกรณีใช้งานจริงเพื่ออธิบายผลของกลไกนี้" ห้ามเขียนกว้าง ๆ เช่น "เพิ่ม ref"
- เดินเรื่องตามลำดับ bullet เว้นแต่พบหลักฐานว่าควรแก้ลำดับในรายการต้นทางก่อน ใช้โครงอธิบายที่เหมาะกับเนื้อหา (เช่น นิยาม → กลไก → ผลที่ตามมา → ขอบเขตการใช้) และอธิบายความสัมพันธ์ระหว่างประเด็น ไม่ใช่แปลง bullet เป็นประโยคทีละข้อ
- **ห้าม `###` มี `####` เพียงหัวข้อเดียวโดยเด็ดขาด** `####` ลูกเดียวต้องตีความว่าเป็น **ประเด็นเนื้อหาที่ `###` ต้องพูดถึง** ไม่ใช่เนื้อหาย่อยที่ควรแยกเป็นหัวข้อ ชื่อของ candidate `####` ใช้ช่วยกำหนดประโยคหัวเรื่อง ลำดับย่อหน้า หรือ checklist ความครบได้ แต่ห้ามนำไป render เป็น heading ใน `prose.md`; ให้เขียนสาระนั้นตรงใต้ `###` หากมีหลายกลุ่มจริงจึงตั้ง `####` อย่างน้อยสองหัวข้อซึ่งแต่ละหัวข้อมีหน้าที่ต่างกันและมีเนื้อหาพอ ห้ามแตกหัวข้อเทียมเพื่อให้ผ่านจำนวนขั้นต่ำ
- **ทุกหัวข้อ `###` ที่มี `####` ตั้งแต่สองกลุ่มขึ้นไปต้องมีย่อหน้าเกริ่นนำของตัวเองก่อน `####` แรกเสมอ** ย่อหน้านี้ทำหน้าที่บอกว่าประเด็นย่อยสัมพันธ์กันอย่างไร เหตุใดจึงเรียงตามลำดับนั้น และผู้อ่านควรใช้กรอบใดเชื่อมจากประเด็นหนึ่งไปสู่อีกประเด็นหนึ่ง ไม่ใช่สรุปชื่อ `####` เป็นรายการ ไม่ลงรายละเอียดซ้ำกับหน่วยร้อยแก้วของ main bullet และไม่นับเป็นส่วนหนึ่งของหน่วยเหล่านั้น ให้เขียนเกริ่นนำนี้หลังร้อยแก้วของ `####` ภายใน `###` นั้นเสร็จแล้ว เพื่อให้สะท้อนโครงเรื่องจริง
- **เกริ่นนำต้องตอบ “ทำไมความสัมพันธ์นี้จึงสำคัญ” ไม่ใช่ทำหน้าที่เป็นสารบัญย่อ**: ต้องอธิบายว่าชื่อหัวข้อใหญ่ตั้งคำถามหรือปัญหาอะไร เหตุใดจึงต้องอาศัยหัวข้อย่อยเหล่านั้นร่วมกัน และความเข้าใจที่ได้ช่วยการวิเคราะห์ การตีความ หรือการตัดสินใจตาม `{{PROFILE:reader-domain-contract}}` อย่างไร ประโยคแบบ “หัวข้อนี้ประกอบด้วย/เริ่มจาก A ต่อด้วย B และจบด้วย C” เพียงอย่างเดียวถือว่าไม่ผ่าน แม้ลำดับจะถูกต้อง; หากยังเขียนได้เพียง roadmap ที่ไม่เพิ่มเหตุผลหรือความสำคัญ ให้กลับไปทำความเข้าใจความสัมพันธ์จากเนื้อหาลูกก่อน และไม่เติมข้อความเยิ่นเย้อเพื่อให้มีเกริ่นนำตามรูปแบบ
- **หัวข้อระดับหนึ่งห้ามมีลูกโดยไม่มีย่อหน้าของตัวเองก่อน** ห้ามวาง `###` แล้วตามด้วย `####` ทันที และห้ามแก้ด้วยเกริ่นนำเทียมเพื่อรองรับลูกเพียงหัวข้อเดียว; ให้ยุบ singleton ก่อน แล้วจึงตรวจว่าการไหลจากชื่อ `###` สู่ย่อหน้าแรกเป็นประโยคอธิบายเนื้อหา ไม่ใช่ข้อความบอกโครงสร้างต้นฉบับ
- ใช้ศัพท์ไทยเป็นหลัก ใส่คำอังกฤษในวงเล็บเมื่อกล่าวศัพท์เฉพาะครั้งแรกภายใน `##` นั้น (ดูหัวข้อ "การใช้ศัพท์") เพื่อให้แต่ละหัวข้อใหญ่เปิดอ่านแยกได้โดยไม่ต้องย้อนหาคำอังกฤษจากส่วนก่อนหน้า

### สัญลักษณ์คณิตศาสตร์ต้องเป็น LaTeX เสมอ

- ห้ามใช้ inline code (backtick `` ` ``) แสดงตัวแปร มิติ หรือสมการ ไม่ว่าในเนื้อความหรือหัวตาราง
- ใช้ `$...$` สำหรับตัวแปร/มิติ/สมการแบบแทรกในบรรทัด เช่น $p = \rho R T$, $\tau = \mu \dfrac{du}{dy}$
- ใช้ `$$...$$` สำหรับสมการหลักที่แยกบรรทัด (display equation)
- เมื่อเนื้อหาจำเป็นต้องแสดงมิติ ให้เขียนแบบ $[M L^{-1} T^{-2}]$ เสมอ ไม่ใช้ `{ML⁻¹T⁻²}` หรือเลขยกยูนิโค้ดแบบเดิม มิติไม่ใช่ข้อมูลบังคับในรายการตัวแปรหลังสมการทั่วไป

### กรอบการอธิบายสมการ 4 ส่วน (บังคับทุกสมการหลักที่แยกบรรทัด)

ห้ามวางสมการหลัก (display equation) ลอย ๆ โดยไม่มีคำอธิบาย ทุกสมการต้องมีองค์ประกอบครบสี่ส่วนตามลำดับนี้:

1. **ข้อความนำ** — อธิบายสถานการณ์ทางกายภาพก่อนขึ้นสมการให้ผู้อ่านสร้างภาพในใจได้ ระบุวัตถุหรือระบบที่พิจารณา ทิศทาง พิกัด เงื่อนไขขอบเขต และสมมติฐานที่จำเป็นก่อนใช้สัญลักษณ์ ห้ามเริ่มด้วยชื่อสมการแล้วข้ามไปยังวัตถุที่ยังไม่เคยนิยาม เช่นกล่าวถึง “แผ่นบน–แผ่นล่าง” หลังสมการโดยไม่บอกก่อนว่าเป็น{{PROFILE:domain-thai-noun}}ระหว่างแผ่นคู่ขนาน ข้อความนำอาจยาวเกิน 1–2 ประโยคเมื่อจำเป็นต่อความเข้าใจ และยังต้องมี citation ตามกฎเดิม
2. **สมการ** — แสดงด้วย `$$...$$` พร้อมเลขกำกับท้ายสมการ (`\tag{1.1}`) เรียงลำดับต่อเนื่องตลอดบท ไม่ผูกกับเลขหัวข้อย่อย
3. **รายการตัวแปร** — bullet ระบุทุกตัวแปรและกลุ่มอนุพันธ์ที่ผู้อ่านต้องตีความ โดยเขียนความหมายก่อนและใส่ตัวแปรในวงเล็บ พร้อมบทบาททางกายภาพและหน่วย SI เช่น "ความเค้นเฉือน ($\tau$) คือแรงแนวสัมผัสต่อหนึ่งหน่วยพื้นที่ มีหน่วย Pa" ห้ามให้เพียงชื่อซ้ำกับหัวข้อ และห้ามกลับเป็นรูป "$\tau$ คือความเค้นเฉือน" ในฉบับใหม่ ปริมาณไร้มิติให้เขียนว่า `เป็นปริมาณไร้มิติ`
4. **ความหมายทางกายภาพและขอบเขต** — อธิบายความสัมพันธ์เชิงคุณภาพด้วยชื่อปริมาณตามด้วยตัวแปรในวงเล็บเมื่อกล่าวครั้งแรกในย่อหน้า เช่น “เมื่อความหนืดพลวัต ($\mu$) สูงขึ้น...” ไม่เขียนย่อหน้าด้วยสัญลักษณ์ล้วนจนผู้อ่านต้องย้อนจำรายการตัวแปร จากนั้นระบุสมมติฐาน/ข้อจำกัดที่ทำให้สมการเป็นจริง

หลังสมการ ห้ามนำตัวแปรช่วยใหม่เข้ามาโดยไม่บอกความหมาย ณ จุดใช้ เช่น หากลดรูปเป็น $u=Vy/h$ ต้องอธิบายก่อนว่า $V$ เป็นอัตราเร็วของอะไร $h$ เป็นระยะใด และกำหนดจุดกำเนิดกับทิศของพิกัด $y$ อย่างไร การอนุมานจากเงื่อนไขขอบเขตไปสู่สมการลดรูปต้องแสดงลำดับเหตุผล ไม่รวมเป็นวลีสั้นแบบ “เงื่อนไขไม่ลื่นไถลกับสมดุลแรงให้...”

มิติ $[M,L,T,\Theta]$ ให้แสดงเฉพาะ (ก) ตารางตัวแปรกลาง/ตารางสรุปต้นบท (ข) หัวข้อที่สอนการวิเคราะห์มิติโดยตรง หรือ (ค) จุดที่ต้องใช้มิติตรวจหรือสร้างสมการ ไม่ใส่มิติซ้ำหลังตัวแปรทุกสมการ เพราะหน่วยกับมิติที่วางคู่กันตลอดเพิ่มภาระการอ่านโดยไม่ช่วยการตีความฟิสิกส์ ในช่วงที่ใช้มิติจริง ต้องแปล $M,L,T,\Theta$ เป็นมวล ความยาว เวลา และอุณหภูมิ พร้อมอธิบายเลขชี้กำลังลบและเชื่อมกับหน่วยอย่างน้อยหนึ่งตัวอย่าง

สมการที่แทรกกลางประโยคบรรยาย (inline, ไม่ได้ยกขึ้นแยกบรรทัด) ไม่บังคับใช้โครงสี่ส่วนนี้ — ถ้ารู้ตำแหน่งที่ต้องมีสมการแบบนี้แต่ยังเขียนไม่เสร็จตอนนี้ ใช้ `::: needs-equation` มาร์คตำแหน่งไว้ก่อน (ดูหัวข้อ "Placeholder marker สำหรับสิ่งที่ยังไม่ได้เขียน" ด้านล่าง)

`tools/check_equation_variable_lists.py` ทำงานอัตโนมัติก่อนสร้าง PDF และหยุดการ build ถ้าสมการที่มี `\tag{...}` ไม่มีรายการตัวแปร หรือรายการไม่ได้ใช้รูป `ความหมาย ($ตัวแปร$) [บทบาททางกายภาพ] มีหน่วย ...` / `ความหมาย ($ตัวแปร$) เป็นปริมาณไร้มิติ` ตัวตรวจนี้คุมรูปแบบ ส่วนการตรวจว่าความหมาย สัญลักษณ์ และหน่วยตรงกับ `VARIABLES.md` ยังเป็นทั้งการตรวจเนื้อหาและ checklist บังคับก่อนปิดบท

### ตารางสรุปบังคับ (Markdown Tables)

ตารางเหล่านี้สร้างจากประโยคที่มี citation รองรับอยู่แล้วในร้อยแก้วเท่านั้น ห้ามเติมข้อมูลใหม่ที่ยังไม่ผ่านการตรวจสอบตามกฎ "การเขียนร้อยแก้ว" ข้างต้น — ถ้ารู้ตำแหน่งที่ต้องมีตารางแบบนี้แต่ยังเขียนไม่เสร็จตอนนี้ ใช้ `::: needs-table` มาร์คตำแหน่งไว้ก่อน (ดูหัวข้อ "Placeholder marker สำหรับสิ่งที่ยังไม่ได้เขียน" ด้านล่าง) — pipeline ใส่ caption "ตารางที่ N.N: ..." เหนือกล่อง placeholder ให้อัตโนมัติ (ตารางแบบสากล caption อยู่เหนือเสมอ ต่างจากรูปที่ caption อยู่ใต้) ไม่ต้องเลขเองหรือเขียน caption แยก

### การอ้างรูป ตาราง และสมการจากเนื้อความ

รูป ตาราง และสมการเป็นส่วนหนึ่งของลำดับคำอธิบาย ไม่ใช่วัตถุที่วางลอยไว้ให้ผู้อ่านเดาเอง จึงใช้หลักร่วมกันดังนี้:

- ต้องมี **ข้อความชี้องค์ประกอบในเนื้อความ** ก่อนถึงรูป ตาราง หรือสมการอย่างน้อย 1–3 ประโยค โดยอ้างเลขผ่าน stable anchor ระบุว่าผู้อ่านควรสังเกตหรือใช้สิ่งใด และอธิบายว่าสิ่งนั้นเชื่อมกับเหตุผลในเนื้อหาอย่างไร
- ข้อความชี้องค์ประกอบเป็นย่อหน้าเสริมด้านการนำเสนอ **ไม่นับเป็นย่อหน้าของ main bullet และไม่อยู่ภายใต้เป้าประมาณ 5 บรรทัด** แต่ห้ามใช้แทนการขยาย main bullet; ข้อเท็จจริงในข้อความชี้ยังต้องมี citation ตามปกติ
- anchor ใช้รูปแบบ `fig-chNN-<คำสั้นเฉพาะรูป>`, `tab-chNN-<คำสั้นเฉพาะตาราง>` และ `eq-chNN-<คำสั้นเฉพาะสมการ>` ต้องไม่ซ้ำทั้งบทและต้องคงเดิมเมื่อเปลี่ยน placeholder เป็นของจริง

**รูป**

- รูปทุกจุดต้องมี **ข้อความชี้รูปในเนื้อความ** ก่อนถึงรูปหรือ placeholder อย่างน้อย 1–3 ประโยค โดยอ้าง `รูปที่ \ref{<anchor>}` ระบุว่าผู้อ่านควรสังเกตอะไรในรูป และอธิบายว่ารูปนั้นเชื่อมกับเหตุผลในเนื้อหาอย่างไร ห้ามวางภาพ/`ref-note` ลอย ๆ โดยไม่มีเนื้อความเรียกใช้
{{PROFILE:book-figure-example-and-conventions}}
**ตาราง**

- ก่อนตารางให้มีข้อความชี้ เช่น `เกณฑ์ทั้งสามเปรียบเทียบในตารางที่ \ref{tab-ch01-state-comparison}` พร้อมบอกว่าควรอ่านตามแถวหรือคอลัมน์ใดและตารางช่วยตอบคำถามอะไร
- ตารางที่เขียนเสร็จแล้วให้ครอบด้วย `book-table` โดยบรรทัดแรกเป็น caption สำหรับผู้อ่าน ตามด้วยตาราง Markdown เช่น

  ```markdown
  ::: {#tab-ch01-state-comparison .book-table}
  การเปรียบเทียบพฤติกรรมของสสารสามสถานะ

  | ... | ... |
  |---|---|
  | ... | ... |
  :::
  ```

  pipeline วาง caption เหนือตาราง ใส่เลขและ `\label` จาก anchor และรักษาเลขตารางให้ต่อเนื่อง หากตารางยังไม่เขียนให้ใช้ `::: {#tab-... .needs-table}` ด้วยหลัก caption/anchor เดียวกัน

**สมการ**

- ข้อความนำของสมการตามกรอบสี่ส่วนต้องอ้างเลขสมการด้วย เช่น `ความสัมพันธ์นี้เขียนได้ดังสมการ \eqref{eq-ch01-newton-viscosity}` และบอกว่าสมการเชื่อมปริมาณใดหรือใช้ตอบคำถามใด ไม่ใช้เพียงคำว่า “จากสมการข้างล่าง”
- ใน display equation ให้กำกับทั้งเลขที่ผู้อ่านเห็นและ stable anchor เช่น `\tag{1.1}\label{eq-ch01-newton-viscosity}` จุดอ้างอื่นใช้ `สมการ \eqref{eq-ch01-newton-viscosity}` เพื่อให้เลขปรับตาม anchor ไม่พิมพ์เลขซ้ำด้วยมือในเนื้อความ

**ตัวอย่างคำนวณ**

- ตัวอย่างคำนวณสามารถเป็น standalone ได้ ไม่บังคับให้มีย่อหน้าชี้ก่อน callout เพราะกรอบมีโจทย์ สมมติฐาน วิธีทำ และการตรวจสอบคำตอบครบในตัวอยู่แล้ว หากตัวอย่างทำหน้าที่สืบต่อข้อสรุปจากเนื้อความหรือถูกนำไปใช้ภายหลัง จึงค่อยเพิ่มประโยคเชื่อมตามความจำเป็น

### ตัวอย่างคำนวณต้องแยกเป็น Callout Block (Worked Examples)

แยกโจทย์คำนวณออกจากเนื้อหาบรรยายหลักเสมอ และใช้ **แม่แบบบังคับเพียงรูปแบบเดียว** ด้านล่าง แต่ละส่วนเป็นหนึ่งย่อหน้าใน blockquote เรียงครบสี่ส่วน ห้ามใช้ `::: worked-example`, ห้ามพิมพ์หัวข้อ/เลข “ตัวอย่างที่ ...” เอง และห้ามเพิ่มส่วน “คำตอบ” แยกต่างหาก—ให้สรุปผลคำนวณไว้ท้าย **วิธีทำ** แล้วตรวจความหมายในส่วน Review:

> **โจทย์:** ...
> **สมมติฐาน:** ...
> **วิธีทำ:** (แสดงการคำนวณทีละขั้นตอนด้วย LaTeX)
> **ตรวจสอบคำตอบ (Review):** (วิเคราะห์ความถูกต้องและนัยสำคัญตามสาขา/ผู้อ่านเป้าหมาย)

ส่วน **โจทย์** ต้องเขียนเป็นภาษาธรรมชาติด้วยชื่อปริมาณและบริบททางกายภาพ ไม่กำหนดตัวแปร ไม่วางสมการ และไม่เขียนข้อมูลในรูป `$x=...$` เช่นเขียนว่า “น้ำมันมีความหนืดพลวัต 0.29 Pa·s แผ่นบนเคลื่อนที่ด้วยอัตราเร็ว 3 m/s...” ไม่เขียน “$\mu=0.29$, $V=3$...” วิธีนี้ทำให้ผู้อ่านต้องตีความสถานการณ์ก่อนเลือกแบบจำลองเหมือนการแก้ปัญหาจริง

ส่วน **วิธีทำ** ต้องเริ่มด้วยการจับคู่ชื่อปริมาณจากโจทย์เข้ากับตัวแปรมาตรฐานใน `VARIABLES.md` พร้อมค่าและหน่วย เช่น “กำหนดความหนืดพลวัต $\mu=0.29$ Pa·s อัตราเร็ว $V=3$ m/s และช่องว่าง $b=0.02$ m” แล้วจึงเลือกสมการ แทนค่า และคำนวณ ส่วนสมมติฐานอธิบายเงื่อนไขของแบบจำลองเป็นคำ ไม่ใช้เป็นที่ซ่อนการกำหนดตัวแปรแทนส่วนวิธีทำ

ตัวอย่างคำนวณทุกข้อ (ทั้งที่เขียนเสร็จเป็น blockquote ข้างบน และที่ยังเป็น `::: needs-example` placeholder) ได้หัวข้อ "ตัวอย่างที่ N.N" ให้อัตโนมัติจาก pipeline (นับต่อเนื่องในบทเดียวกัน ไม่สนใจว่าจะเป็นของจริงหรือ placeholder) ไม่ต้องใส่เลขเอง — เขียนแค่ `> **โจทย์:** ...` ตามโครงสี่ขั้นด้านบนให้ครบ pipeline จะจับคำว่า "โจทย์" ที่ตัวหนาต้นบรรทัดแรกแล้วแปลงเป็นกล่อง callout สีส้มพร้อมเลขให้เอง

ตัวตรวจใน `citations.lua` บังคับโครงสี่ส่วนนี้ระหว่าง build: ถ้าขาดส่วนหนึ่ง เรียงผิด ใช้ fenced Div แทน blockquote หรือพิมพ์เลขเองใน Div การ build ต้องหยุดพร้อมแจ้งข้อผิดพลาด เพื่อไม่ให้ตัวอย่างหลุดเป็นข้อความธรรมดาหรือทำให้เลขทั้งบทคลาดเคลื่อน นอกจากนี้ `tools/check_worked_example_statements.py` บังคับว่าส่วนโจทย์ต้องไม่มี LaTeX variable/สมการ และส่วนวิธีทำต้องมีการกำหนดสัญลักษณ์กับค่า ก่อนส่งต่อให้ Pandoc

ถ้ารู้ตำแหน่งที่ต้องมีตัวอย่างคำนวณแบบนี้แต่ยังเขียนไม่เสร็จตอนนี้ ใช้ `::: needs-example` มาร์คตำแหน่งไว้ก่อน (ดูหัวข้อ "Placeholder marker สำหรับสิ่งที่ยังไม่ได้เขียน" ด้านล่าง) — และถ้าย่อหน้าบรรยายมีภาพสไลด์อ้างอิงอยู่ที่ยังไม่ใช่ภาพจริงของหนังสือ ใช้ `::: ref-note` กำกับแยกไว้เป็นคนละสถานะกับ marker ที่ยังไม่มีอะไรเลย

## บทนำระดับ `#` (บท), `##` (หัวข้อใหญ่) และ `###` (หัวข้อย่อย)

เขียน**ทีหลังสุดเสมอ** หลังร้อยแก้วในขอบเขตนั้นเสร็จสมบูรณ์แล้วเท่านั้น เพราะบทนำต้องสะท้อนเนื้อหาจริงที่เขียนไว้ ไม่ใช่คาดเดาล่วงหน้าว่าจะเขียนอะไร

- **ระดับ `#` (ทั้งบท)** — หนึ่งย่อหน้าสั้น วางหลังหัวข้อ `#` ก่อนหัวข้อ `##` แรก ทำหน้าที่ (1) เชื่อมโยงจากบทก่อนหน้าตามความจำเป็น หากมีความสัมพันธ์จริง เช่นบทนี้ต่อยอดหรือใช้ผลจากบทก่อน (2) เล่าความสำคัญของบทในภาพรวม เหตุใดผู้อ่านเป้าหมายจึงต้องเรียนเรื่องนี้ และใช้ในบริบทใดตาม `{{PROFILE:reader-domain-contract}}` (3) ปูภาพรวมคร่าว ๆ ของหัวข้อ `##` ทั้งหมดในบท โดยไม่ลงรายละเอียดระดับ `###`/`####`
- **ระดับ `##` (หัวข้อใหญ่)** — วางหลังหัวข้อ `##` ก่อนเนื้อหา `###` แรก (หรือก่อน slide block ถ้ามี) ทำหน้าที่อธิบาย**ความสัมพันธ์ระหว่างหัวข้อ `###` ภายในหัวข้อนี้เท่านั้น** เช่น ลำดับจากนิยาม → กลไก → การประยุกต์ → ข้อจำกัด เพื่อช่วยผู้อ่านเห็นว่าทำไมหัวข้อย่อยเหล่านี้จึงเรียงกันแบบนี้ — **ห้ามซ้ำ**กับการเล่าความสำคัญภาพรวมที่ทำไปแล้วในบทนำระดับ `#`
- **ระดับ `###` ที่มี `####` ตั้งแต่สองกลุ่มขึ้นไป** — วางบทนำหลังหัวข้อ `###` ก่อน `####` แรก เพื่อชี้ความเชื่อมโยงระหว่างกลุ่ม เช่น สิ่งที่สังเกตได้ → กลไก → เกณฑ์ → ข้อจำกัด; หาก `###` ไม่มี `####` ย่อหน้าแรกคือการเริ่มอธิบายเนื้อหาโดยตรง ไม่ต้องสร้างบทนำแยกอีกชั้น

**ทำไมบทนำ `##` สำคัญกว่าที่ดูตอนแรก**: ย่อหน้าระดับ `####` แต่ละย่อหน้าถูกบังคับให้กระชับและผูกกับหลักฐานแน่น (หนึ่งประเด็นต่อย่อหน้า อ้างอิงทุกประโยค) จึงมักอ่านแล้ว "แข็ง" ไม่เห็นความเชื่อมโยง เหตุผล หรือที่มาที่ไประหว่างหัวข้อย่อย — ความน่าสนใจ ความเชื่อมโยง และเหตุผลเชิงภาพรวมทั้งหมดจึงตกเป็นภาระของบทนำ `##` นี้เกือบทั้งหมด อย่าจำกัดตัวเองไว้แค่ "สอง–สามประโยค" ถ้าหัวข้อ `##` นั้นมี `###` ย่อยหลายหัวข้อที่ต้องร้อยเรียงเหตุผลเชื่อมกัน ให้ยาวเท่าที่จำเป็นเพื่อเล่าว่าทำไมหัวข้อย่อยจึงเรียงแบบนี้ อะไรเป็นเหตุเป็นผลของอะไร และทำไมผู้อ่านควรสนใจ — ยังคงห้ามลงรายละเอียดระดับ `####` (ตัวเลข สูตร ผลการทดลอง) แต่การเล่าเหตุผล/ที่มาที่ไปเชิงโครงสร้างทำได้เต็มที่

บทนำทั้งสามระดับสั้นกว่าเนื้อหาระดับ `####` เพราะหน้าที่คือปรับทิศทางผู้อ่านและร้อยเรียงภาพรวม ไม่ใช่อธิบายเนื้อหาเจาะลึก — ประโยคปูภาพรวม/roadmap แบบ "หัวข้อนี้ครอบคลุม..." ใช้ได้เฉพาะสามระดับนี้เท่านั้น (ต่างจากกฎห้ามพูดถึงกระบวนการเขียนในย่อหน้าระดับ `####` ข้างต้น) ข้อความที่อ้างข้อเท็จจริงเฉพาะเจาะจง เช่นตัวเลขหรือผลต่อการปฏิบัติในสาขาที่หยิบมาโดยตรง ยังต้องมีหลักฐานรองรับตามปกติ ส่วนประโยคเชื่อมโยงโครงสร้าง/ลำดับหัวข้อ/เหตุผลภาพรวมถือเป็นดุลยพินิจผู้เขียน ไม่ต้องมี citation

## ข้อควรระวังและข้อจำกัดของวิธีการนี้

**1. อ้างเกินหลักฐานที่มีจริง (over-citing)** — ความเสี่ยง: ใช้ citation ระดับมาตรา/บทกว้าง ๆ แทนเลขหน้าจริง, ยืมเลขหน้า/สมการจากหน่วยหลักฐานหนึ่งไปแปะประโยคข้างเคียงที่ไม่ได้ตรวจจากหน้านั้นจริง, ขยายขอบเขตสูตร/ตัวเลขเกินที่ต้นฉบับระบุ (เช่นต้นฉบับพูดกรณีเฉพาะแต่เขียนเหมือนเป็นกฎทั่วไป) แก้ไข: ทุก citation ต้องตอบได้ว่า "เปิดหน้านี้แล้วเห็นประโยคนี้จริงหรือไม่" — ตอบไม่ได้ทันทีให้เปิดตรวจซ้ำก่อนใส่

## การตรวจสอบก่อนเขียนร้อยแก้ว (ทำทั้งบทครั้งเดียว ไม่ใช่ทีละหัวข้อ)

**ห้ามเริ่มเขียน `prose.md` ของบทใดก่อนบทนั้นผ่านเกทนี้** — เขียน prose บนโครงที่ยังมีปัญหาเชิงระบบ (เช่น nesting ตื้นทั้งบท) ทำให้ต้องรื้อร้อยแก้วที่เขียนไปแล้วซ้ำ เสียทรัพยากรมากกว่าแก้ตั้งแต่ชั้น `chapter.md` มาก — เกทนี้จึงบังคับ ไม่ใช่ทางเลือก

รันสคริปต์ตรวจโครงสร้างอัตโนมัติก่อนเสมอ (ครอบคลุมข้อ 1–7 ด้านล่างในคำสั่งเดียว ยกเว้นข้อ 8 ที่ต้องอ่านตาม logic เอง):

```bash
{{PROFILE:text-extraction-python}}3 tools/check_chapter_structure.py {{PROFILE:manuscript-root}}/chXX_xxx
```

สคริปต์นี้ "ชี้เป้า" เท่านั้น ไม่ตัดสินแทนคน — ทุกจุดที่มันรายงานต้องเปิดตรวจด้วยสายตาว่าเป็นปัญหาจริงหรือ false positive (เช่นข้อ 5 ที่เทียบเลข Eq./Fig. แบบ substring อาจชนกับตัวเลขอื่นในบูลเล็ตโดยบังเอิญ) แก้เฉพาะ section ที่ fail แล้ว re-run จนทุกหัวข้อผ่านก่อนเริ่มเขียนร้อยแก้วจริง:

1. **ภาษาของหัวข้อ** — เช็ค `chapter.md` แล้ว Thai-ify เฉพาะตอนตั้งชื่อหัวข้อใน `prose.md` (ดู "การใช้ศัพท์") หัวข้อใน `chapter.md` เองมีอังกฤษปนได้ตามปกติเพราะมาจาก master outline ห้ามแก้ที่นี่ — สคริปต์รายงานไว้เป็นข้อมูลอ้างอิงล่วงหน้าเท่านั้น
2. **ความลึก nested bullet** — วัด indentation สูงสุดของแต่ละ `### x.x.x` (ต้องถึง 6 ช่องว่าง/ระดับ 3 เว้นแต่เข้าเงื่อนไข "กับดักปลอม" หรือหลักฐานไม่พอจริง — ทุกหัวข้อที่สคริปต์รายงานว่าไม่ถึงต้องเปิด `EVIDENCE_x.x.x.md` ตรวจว่ามีสาย เหตุผล→กลไก→ตัวเลข/ตัวอย่าง ที่ยังไม่ถูกนำมาขยายเป็นบูลเล็ตจริงหรือไม่ ก่อนจะยอมรับว่า "หลักฐานบางจริง")
3. **ไฟล์ evidence ledger ครบ** — ทุกหัวข้อต้องมี `references/EVIDENCE_x.x.x.md`
4. **ไม่มี citation ที่ขาด source-native locator** ภายใน bullet (กล่อง "แหล่งอ้างอิงแนะนำ" ท้ายหัวข้อยกเว้น เพราะเป็นแค่รายการอ่านแนะนำ ไม่ใช่ citation ระดับหลักฐาน)
5. **ตาราง/รูป/สมการ/ตัวอย่างใน evidence ledger ต้องปรากฏใน bullet ด้วย** — เทียบ `Eq./Fig./Table/Example` ใน `EVIDENCE_x.x.x.md` กับข้อความ bullet ของหัวข้อเดียวกัน
6. **หัวข้อซ้ำ** — ไม่มี `##`/`###` ซ้ำกัน
{{PROFILE:structure-check-spelling-rule}}8. **fake nesting ด้วยสายตา** — สคริปต์ตรวจความลึกได้ แต่ตรวจ "ความสัมพันธ์สืบทอด" ไม่ได้ ต้องไล่อ่านทุก bullet ที่ลึกถึงระดับ 2–3 เองว่าเป็นการขยายความจริง ไม่ใช่ขั้นตอน/กรณีคู่ขนาน/การเปรียบเทียบที่ถูกบังคับซ้อนกัน (ดูสัญญาณเตือนในหัวข้อ "การสร้าง `####` ประเด็นที่จะอธิบายตามลำดับ" ด้านบน)
9. **รูปที่แกะจาก PDF** — ถ้าไม่มี `references/figures/` เลยทั้งบท (สคริปต์เตือนไว้) ให้ทบทวนว่าหน้าที่เปิดอ่านจริงมีรูป/ตาราง/แผนภูมิที่ควรดึงด้วย `--images` เก็บไว้เป็น compositional reference หรือไม่ — ไม่บังคับทุกหน้า (หลายหน้าเป็นข้อความล้วน) แต่ต้องเป็นการตัดสินใจที่ตรวจแล้ว ไม่ใช่ลืมทำ

## การใช้ศัพท์

- ตรวจ [อภิธานศัพท์](../{{PROFILE:manuscript-root}}/GLOSSARY.md) ก่อนเขียนร้อยแก้วทุกหัวข้อ ใช้ศัพท์บัญญัติภาษาไทยเป็นหลัก และตามด้วยอังกฤษในวงเล็บเมื่อ **ศัพท์หลักที่ `##` นั้นกำลังสอน** ปรากฏครั้งแรกในร้อยแก้วของ `##` เช่น `ความเค้นเฉือน (shear stress)` — การกล่าวในตารางสัญลักษณ์ สารบัญ caption, heading หรือหัวข้อก่อนหน้าไม่นับแทนการแนะนำในร้อยแก้วของ `##` ปัจจุบัน หลังจากครั้งแรกใน `##` เดียวกันใช้ไทยเป็นหลัก ยกเว้นจำเป็นต่อสมการ สัญลักษณ์ มาตรฐานวิชาชีพ หรือกันความกำกวม ศัพท์ประกอบทั่วไปที่นิยามไปแล้วและเพียงถูกเอ่ยผ่านไม่ต้องใส่อังกฤษซ้ำทุกครั้ง
- บทนำระดับ `#` ใส่ English term ได้เฉพาะศัพท์แกนของทั้งบทที่เกิดขึ้นอย่างเป็นธรรมชาติ เช่น `{{PROFILE:domain-thai-noun}} (คำอังกฤษตาม glossary)` ห้ามกองศัพท์ทั้งหมดไว้ที่ต้นบทเพื่อหลีกเลี่ยงการแนะนำใน `##`; ตำแหน่งหลักสำหรับ technical term คือประโยคแรกที่ใช้จริงในแต่ละ `##`
- ไม่ยัดวงเล็บหลายคำจนประโยคอ่านยาก หาก `##` มีศัพท์ใหม่หลายคำ ให้กระจายการแนะนำไปยังย่อหน้าแรกที่อธิบายแต่ละแนวคิด โดยต้องเกิดก่อนใช้คำย่อ สัญลักษณ์ หรือคำอังกฤษนั้นโดยไม่มีคำแปล
- ก่อนปิด `##` ให้ทำรายการศัพท์หลักจากชื่อ `##`, ชื่อ `###` และแนวคิดที่นิยาม/เปรียบเทียบ/ใช้คำนวณจริง แล้วตรวจทีละคำว่า (1) มีรายการใน `GLOSSARY.md` (2) ครั้งแรกในร้อยแก้วของ `##` เป็น `ไทย (English)` และ (3) ครั้งหลังใช้ไทยเป็นหลัก รายการนี้เป็นการตรวจเชิงความหมาย ห้ามนับการพบคำใน heading หรือตารางสัญลักษณ์ว่า “แนะนำแล้ว”
{{PROFILE:book-terminology-rule}}- ใช้รูปศัพท์เดียวกันสม่ำเสมอตลอดหัวข้อและทั้งบท เมื่อพบศัพท์ใหม่ให้เพิ่มในอภิธานศัพท์ (ไทย/อังกฤษ/ความหมาย/ตำแหน่งที่ปรากฏครั้งแรก/หลักฐาน) ก่อนใช้ในร้อยแก้ว — ถ้าแหล่งต่างกันใช้คำต่างกัน ให้บันทึกคำที่เลือกและหลีกเลี่ยงสลับรูปศัพท์โดยไม่มีเหตุผล
- **หัวข้อ (`##`/`###`/`####`/`#####`) ใช้ศัพท์ไทยเป็นหลักเช่นเดียวกับเนื้อความ** ก่อนตั้งชื่อหัวข้อ ให้ตรวจว่าคำอังกฤษที่จะใช้มีคำไทยบัญญัติอยู่แล้วใน `GLOSSARY.md` หรือถูกใช้เป็นคำไทยในร้อยแก้วของหัวข้อนั้นเองหรือไม่ (เช่น "มอดุลัสเชิงปริมาตร" มีอยู่แล้ว ไม่ตั้งหัวข้อว่า "bulk modulus of elasticity") คงคำอังกฤษไว้ในหัวข้อได้เฉพาะชื่อเฉพาะ/สัญลักษณ์มาตรฐานที่ไม่มีคำไทยเทียบเท่าจริง ๆ (เช่น SI, BG) หรือชื่อวิธี/กฎที่ตั้งตามคน (เช่น Grid Method) — กรณีนี้สะกดตัวพิมพ์ใหญ่ตัวแรกของคำเสมอ (title case) ไม่ใช้ตัวพิมพ์เล็กขึ้นต้น

## เกณฑ์ตรวจรับ — เนื้อหาและหลักฐาน

- [ ] ร้อยแก้วตอบทุกองค์ประกอบที่ชื่อหัวข้อสัญญาไว้ด้วยข้อความตรงหรือองค์ประกอบช่วยอ่านที่ชัดเจน; ผู้อ่านไม่ต้องอนุมานคำตอบจากการมีสมการหรือตัวอย่างเพียงอย่างเดียว
- [ ] สาระจากโซนข้อความและภาพ {{PROFILE:primary-teaching-source-label}} ปรากฏครบ (ไล่เทียบทีละบรรทัด)
- [ ] ไม่มี citation ที่อ้างเกินสิ่งที่เปิดอ่านพบจริง (เลขหน้าเจาะจง ไม่ใช่มาตรากว้าง ๆ)
- [ ] ตาราง/รูป/สมการ/ตัวอย่างที่หลักฐานอ้างถึงมี bullet `[มีตารางประกอบ ...]`/`[มีรูปประกอบ ...]`/`[มีตัวอย่างประกอบ ...]` ระบุตำแหน่ง
- [ ] nested bullet ที่ลึกถึง 3 ระดับสื่อความสัมพันธ์สืบทอด/เฉพาะเจาะจงขึ้นจริง ไม่ใช่ลำดับ/กรณีคู่ขนาน/การเปรียบเทียบที่ถูกบังคับซ้อนกัน

- [ ] ทุก bullet ชี้กลับหลักฐานที่เปิดอ่านจริงได้ ไม่มี bullet จากความรู้เดิม/การคาดเดา
- [ ] main bullet ทุกข้อเป็นประโยคบอกเล่าความเดียว มี nested bullet ขยายความเพียงพอ อ่านเข้าใจได้ด้วยตัวเอง
- [ ] ลำดับร้อยแก้วตรงกับรายการประเด็น แต่ละ main bullet ขยายเป็นหน่วยเหตุผลที่มีคำอธิบาย+ตัวอย่างจากหลักฐานและติดตามย้อนกลับได้ แม้หน่วยนั้นแบ่งเป็นหลายย่อหน้า
- [ ] ย่อหน้าไม่สั้นจนเหลือกล่าวซ้ำ bullet และไม่ยาวจนรบกวนการอ่าน — สั้นกว่า ~5 บรรทัดได้เมื่อหลักฐานจำกัด และแบ่งหลายย่อหน้าได้เมื่อช่วยจังหวะความคิดโดยไม่แตกประเด็นออกนอก main bullet
- [ ] ร้อยแก้วไม่กล่าวถึงกระบวนการเขียน/ชื่อแหล่งในเนื้อความ ไม่มีข้อสรุปเกินหลักฐาน

- [ ] ไม่มี `###` ใดมี `####` เพียงหัวข้อเดียว; `###` ที่มี `####` ตั้งแต่สองกลุ่มขึ้นไปมีเกริ่นนำก่อนกลุ่มแรก ส่วน `###` ที่ไม่มี `####` เริ่มอธิบายเนื้อหาโดยตรง; ทุกหัวข้อ `##` มีบทนำอธิบายความสัมพันธ์ของ `###` ภายใน และหัวข้อ `#` มีบทนำเล่าความสำคัญของบท+เชื่อมบทก่อนหน้า+ปูภาพรวม `##`
- [ ] ร้อยแก้วที่เขียนเสร็จอยู่ใน `prose.md` (ไม่ใช่ `chapter.md`) เรียงลำดับตรงกับ outline, ภาพสไลด์ที่เกี่ยวข้องแทรกอยู่ในตำแหน่งย่อหน้าที่ถูกต้อง และ `chapter.md` มีบรรทัดชี้กลับไปยัง `prose.md` โดยยังเก็บ `#### ประเด็นที่จะอธิบายตามลำดับ` และ bullet หลักฐานไว้ครบ
